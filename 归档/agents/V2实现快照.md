# V2 实现快照

这是一份历史快照，记录 V2 收口后已经稳定但不再适合堆在活跃 `AGENTS.md` 里的实现细节。当前开发时，是否仍视为活跃契约，以 live 文档、代码和测试为准。

## Retrieval
- 默认生产检索路径由 `InfinityHybridRetriever` 与 `InfinityDenseVectorIndex.search_hybrid()` 承接。
- retriever 继续使用 `embed_query(raw query)` 做 dense embedding，同时对 sparse 分支做 query 分析；dense 分支保留原始 query。
- hybrid sparse 匹配字段为 `filename` 与 `text`；诊断型 `search_text()` 保持单字段 `text` 语义。
- `search_hybrid()` 会先扩大候选再裁回 `top_k`，并在 Infinity fusion 结果上应用 bounded position prior：

```text
adjusted_score = fused_score + 0.03 / (1 + chunk_index)
```

- 该策略是内部收口，不提升为公共配置，也不引入 rerank、tag API 或额外主路径；内部字段 `_chunk_index` 不泄漏到 `RetrievedChunk.metadata`。

## Citation And Parser Baseline
- OpenAI Responses answerer 按 score 降序给 contexts 编号为 `[1]`..`[n]`，提示模型使用 `<cite:n>`；输出后把合法 `<cite:n>` 转为用户可见 `[n]`，移除越界或非法 token。
- PDF 页感知 citation 元数据链路为：`BasicPdfParser` 在 metadata 中写入 `page_texts`，pipeline 基于归一化文本构造 `page_spans`，`FixedWindowChunker` 写入 `page_start` / `page_end`，answerer 在 prompt 中生成 `page:` 或 `pages:` 行。
- `page_texts` 与 `page_spans` 是内部键，不进入 chunk metadata 或 document catalog。
- 固定 parser strategy 映射为：`txt -> plain_text`、`md -> markdown_flatten`、`pdf -> pdf_native_text`；`CompositeParser` 按 `file_type` 分派，每个 parser 在 `ParsedDocument.metadata` 写入 `parser_strategy`。
- `pdf_native_text` 保持数字原生 PDF 路径，不做 OCR fallback。

## Storage And SDK Snapshot
- `InfinityDenseVectorIndex` 除 dense / hybrid retrieval 外，还承接 `DocumentCatalog` 读路径与 `DatasetStore` dataset 管理 / 绑定。
- `index_document()` 会把 `asset.metadata` 写入 `parser_metadata_json`；`list_documents()` / `get_document()` 填充 `dataset_id`。
- dataset 与 binding 数据使用从 `document_table` 派生的 `<document_table>_datasets` 和 `<document_table>_dataset_bindings` 内部表。
- 当前 embedding 维度契约为 `2048`。
- Infinity SDK 侧约定：`to_pl()` 返回 `(polars.DataFrame, extra_dict)`，`show_columns()` 返回 `polars.DataFrame`。

## Logging Boundary
- infra 只在明确的异常翻译或吞异常边界记日志，例如 `parser_failed`、`local_index_write_failed`、startup / rollback failure。
- 应用层负责主链路级 outcome 日志与业务指标；infra 不扩散 provider debug trace，也不记录原始文档内容、完整 query 或高基数字段。
