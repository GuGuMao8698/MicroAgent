# HyDE

## 目标
- 通过假设文档嵌入缩小“用户问题”和“答案性文档”之间的语义鸿沟。
- 先生成一段包含关键术语的假设答案，再用该文本参与检索。

## 为何排在当前顺序
- `HyDE` 仍属于 query-side 增强，但它引入额外的生成成本和噪声风险，因此排在 `MQE` 之后。
- 在 `MQE` 收益和稳定性已有基础判断后，再引入 `HyDE`，更容易衡量它的独立增益和回退价值。

## 预期收益
- 改善专业领域查询、答案式表达明显强于问题式表达的场景。
- 为统一扩展检索框架补充第二类扩展来源，不再只依赖 query rewrite。

## 边界
- `HyDE` 不应提前变成默认必经路径；它需要保留关闭开关和单独评估空间。
- 当前阶段只固定排期位置、收益预期和使用边界，不展开到 prompt、模型或阈值细节。
