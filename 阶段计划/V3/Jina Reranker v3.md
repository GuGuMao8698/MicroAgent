# Jina Reranker v3

## 目标
- 在现有 Infinity hybrid 初筛之后增加内部重排，提升最终候选片段的相关性排序质量。
- 保持默认生产检索主路径不变，不引入新的公共配置形态或新的外部 API 路径。

## 放置位置
- 放在基础召回之后、回答生成之前，作为内部 rerank 步骤消费候选 chunk 列表。
- 与异步 ingestion pipeline 解耦；它属于 query-time 检索优化，不承担文档入库职责。

## 当前状态
- 作为 `V3` 既有主任务之一，排在异步 ingestion pipeline 收口之后继续推进。
- 当前文档只记录阶段目标与边界，不展开到具体模型接入、参数和测试实现细节。

## 验证重点
- 重排后 top-k 候选是否更贴近用户问题，且不引入明显的召回倒退。
- 与后续 `MQE`、`HyDE`、`RAPTOR` 组合时，职责仍保持为“候选重排”而不是额外召回主路径。
