# 多路扩展检索编排

# 目标

在 `MQE` 与 `HyDE` 之上补齐统一的多路扩展检索编排层，让系统能够用一致入口调度原始 query 和各类扩展输入的检索执行。V3 的最小实现只负责“扩展输入如何组织并触发检索”，不负责候选去重和分数组合。

# 范围与非目标

本文件只定义多路扩展输入的组织方式、每一路如何调用同一检索入口、以及如何产出带来源信息的原始候选包。它不定义候选去重、不定义分数组合、不定义 reranker 接入，也不重新定义 `MQE` 或 `HyDE` 自身的生成逻辑。V3 不在本文件扩展动态策略学习、复杂流量分配器或最终排序公式。

# 核心契约

编排层的输入是一组来源明确的检索路由，每一路至少包含 `route_id`、扩展来源类型和实际用于检索的文本；其中原始 query 也是一路。编排层必须以统一检索入口对每一路执行检索，并将结果按“路由维度”保留下来。最小输出不是最终合并列表，而是一个原始候选包：其中每个候选都附带它来自哪一路、在该路中的顺位和原始检索分值。

该编排层只解决“多路输入如何以一致方式进入检索器”以及“如何把多路原始候选稳定收集回来”两个问题。它可以采用串行或并行执行，但必须对外表现为统一的候选包契约，而不是每种扩展策略各自定义一套检索接口。编排层不能在此阶段提前做跨路去重、不能计算最终组合分数，也不能把 reranker 逻辑折叠进来；这些都属于下游独立能力。

# 验收口径

先失败的条件是：编排层仍要求 `MQE`、`HyDE` 各自维护专用检索入口、它输出的是已经合并排序完成的最终候选、它在内部做了跨路去重、或它没有为候选保留路由来源与路内顺位。通过后的可观察结果是：原始 query 与扩展输入可以通过同一入口被检索；系统能拿到带路由来源的原始候选包；单路和多路执行共享同一输出形状；后续去重与分数组合能只消费这份候选包而不需再回查执行细节。

# 依赖与边界

本文件依赖 `MQE`、`HyDE` 或未来其他扩展源提供来源明确的输入，但它并不要求这些扩展源必须同时存在；只有原始 query 时也应能按同一契约工作。它向下依赖统一的检索入口，向上为候选去重与分数组合提供原始候选包。本文件只对“如何组织并执行多路检索”负责，不对“每一路如何生成、候选如何去重、分数如何组成最终排序”负责。
