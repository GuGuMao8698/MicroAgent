# 候选去重与分数组合

# 目标

在多路扩展检索之后，把不同路由返回的原始候选收敛成一份稳定、可排序的候选列表。V3 的最小实现只负责跨路候选去重、保留命中证据并计算一个统一的组合分数，不负责触发检索或执行 reranker。

# 范围与非目标

本文件只定义多路原始候选如何识别为同一条候选、如何保留多路命中证据以及如何产出一个稳定的组合分数。它不定义多路检索如何调度、不定义 `MQE` 或 `HyDE` 如何生成扩展输入，也不定义 reranker 的接入逻辑。V3 不在本文件引入学习排序、复杂特征工程或跨阶段反馈回路。

# 核心契约

本能力的输入是多路扩展检索编排层产出的原始候选包。候选去重必须依赖稳定的规范标识，例如 canonical chunk id；同一候选即使被多路命中，也只能在输出列表中保留一条记录。输出记录必须保留合并前的命中证据，包括命中了哪些路由、各路由中的顺位以及原始检索分值，避免去重后丢失可解释性。

V3 的最小组合分数采用基于路内顺位的可比规则，而不是依赖不同路由间原始分值天然可比。每一路对同一候选贡献一个 `1 / (rank + 1)` 的路由分值，候选的 `composed_score` 等于其在所有命中路由中的路由分值之和；若需要打平，先比较最佳路由顺位，再比较首次出现顺序。这样可以让“多路一致命中”自然获得更高分，而不必把不同路由的原始检索分数硬拼成统一量纲。

该能力的输出是一份去重后的候选列表，每条候选都带有 `composed_score` 和命中证据，可供下游直接截断或继续交给内部 reranker。它不能在本文件内反向触发检索、不能定义扩展来源生成策略，也不能把 reranker 分数并入 `composed_score`；`composed_score` 只表达多路原始检索命中的聚合结果。

# TDD 验收

先失败的条件是：多路命中的同一候选在输出中仍重复出现、输出候选丢失路由来源证据、组合分数依赖不同路由原始分值可比这一隐含前提、或本能力需要自行重新执行检索才能工作。通过后的可观察结果是：同一 canonical chunk 只保留一条记录；每条记录都能回看其命中路由和顺位；多路共同命中的候选会获得更高的 `composed_score`；下游可以直接消费这份列表而不需要重新理解原始候选包。

# 依赖与边界

本文件依赖多路扩展检索编排层提供带路由来源、路内顺位和原始分值的原始候选包，同时依赖候选对象存在稳定的 canonical 标识。它的输出可以交给截断逻辑或 `Jina` 内部重排继续处理，但不反向规定这些下游能力的实现方式。本文件只对“如何把多路原始候选收敛成一份稳定列表”负责，不对“如何发起检索、如何生成扩展输入、如何做最终回答生成”负责。
