# 多查询扩展

# 目标

通过生成一组与原问题语义等价或互补的扩展 query，提升召回率并缓解用户用词与文档表达不一致的问题。V3 的最小实现只负责把单一 query 扩成一组可检索的查询文本，不在本篇中处理后续检索编排或候选合并。

# 范围与非目标

本文件只定义 `MQE` 如何从原始 query 生成一组有界、可追踪的扩展 query，以及这些扩展 query 需要保留哪些最小元数据。它不定义检索调度、不定义候选去重与分数组合、不定义 reranker 接入，也不改变基础索引结构。V3 不在本文件引入批量实验框架、复杂策略路由或生成式答案草稿。

# 核心契约

`MQE` 的输入是原始用户 query；输出是一个有界的扩展 query 列表，其中必须保留原始 query，并为每个扩展项标记稳定来源，例如 `original` 或 `mqe_rewrite`。扩展集合必须去除完全重复或仅做无意义表面变化的 query，避免把噪声扩写伪装成新增信号。最小实现关注“产出什么可供检索的 query 集合”，不直接决定这些 query 如何并行执行，也不决定多路候选如何合并。

`MQE` 必须保持可关闭和可独立评估。当该能力关闭时，系统仍能退回单 query 检索主路径；当该能力开启时，下游只会看到一组结构一致、来源明确的 query 输入，而不需要同时接收额外的融合分数、最终排序结果或 reranker 产物。这样可以让 `MQE` 成为可插拔的 query 扩展源，而不是新的检索主控器。

# 验收口径

先失败的条件是：`MQE` 在没有下游编排器时无法单独产出扩展 query、它直接返回最终候选而不是 query 集合、它把去重和分数组合并入自身、或关闭后系统无法退回单 query 路径。通过后的可观察结果是：同一原始 query 能稳定产出带来源标记的扩展 query 集合；重复扩展会被剔除；关闭 `MQE` 后系统仍以原 query 正常工作；评估时可单独比较“只用原 query”和“原 query + 扩展 query”两种输入差异。

# 依赖与边界

本文件属于 query-time 增强能力，不依赖 ingestion 结构变化。它可以作为后续多路扩展检索编排的一个输入源，但不反向规定编排层的并发策略、候选池上限或最终排序规则。`HyDE` 也是另一类扩展来源，但它的生成对象和风险模型不同，不能在本文件内混写成统一实现。
