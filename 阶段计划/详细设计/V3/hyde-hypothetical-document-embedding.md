# HyDE 假设文档检索

# 目标

通过生成一段答案式的假设文档，缩小“用户问题表达”和“答案性文档表达”之间的语义鸿沟。V3 的最小实现只负责从原始 query 产出一段可用于检索的假设文档，并把它作为独立扩展输入交给下游消费。

# 范围与非目标

本文件只定义 `HyDE` 的最小输入输出、假设文档的角色以及可关闭边界。它不定义多 query 编排、不定义候选去重与分数组合、不定义最终排序，也不在本篇中展开 prompt、模型供应商或阈值微调细节。V3 不在本文件把 `HyDE` 扩展成默认必经主路径。

# 核心契约

`HyDE` 的输入是原始用户 query；输出是一个带来源标记的假设文档文本，它描述“如果存在理想答案，答案性文档大致会包含哪些术语和表述”。该假设文档是检索辅助材料，不是用户可见的最终答案，也不是评分依据。最小实现只要求 `HyDE` 产出一段可独立嵌入或可独立转交给检索器的文本，并保留它与原始 query 的关联。

`HyDE` 必须保持单路、可关闭和可独立评估。它不能直接接管多路检索编排，不能自行合并候选结果，也不能把生成出的假设文档伪装成最终回答返回给用户。关闭 `HyDE` 后，系统仍应回到原始 query 或 `MQE` 的正常路径；开启 `HyDE` 后，下游只额外获得一个来源明确的扩展输入，而不是一整套新的融合逻辑。

# TDD 验收

先失败的条件是：`HyDE` 必须成为默认必经步骤才能工作、它把生成文本直接当作最终答案返回、它在自身内部执行了候选合并或最终排序、或它无法与原始 query 建立稳定关联。通过后的可观察结果是：系统可以从单一 query 稳定生成一段假设文档；该文档能作为独立扩展输入被检索侧消费；关闭 `HyDE` 后主链路仍可工作；评估时可单独比较是否引入 `HyDE` 带来的召回差异。

# 依赖与边界

本文件属于 query-time 增强能力，不要求修改基础索引或 ingestion 流程。它可以作为多路扩展检索编排的一个输入源，但不定义这些输入如何调度、如何去重、如何做分数组合。与 `MQE` 相比，`HyDE` 的最小实现是“生成一段假设文档”，而不是“生成多个 query rewrite”；两者可以并存，但不能在同一篇文档中混成统一扩展器。
