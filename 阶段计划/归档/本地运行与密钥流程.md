# 本地运行与密钥流程

这份文档保存低频但仍可能需要回看的本地工作流。活跃开发约束以根 `AGENTS.md` 和 `docker/AGENTS.md` 的精简摘要为准。

## Python Workflow
- 仓库包含本地 `.venv`；在仓库根运行 Python 相关命令时，默认使用这个环境。

## Secret Workflow
- 本机开发环境约定是 `WSL2 Debian`。
- `OPENAI_API_KEY`、`ARK_API_KEY` 和 `ARK_EMBEDDING_MODEL` 统一通过 `pass` 管理，不写入仓库内 `.env` 或其他项目文件。
- 历史上默认使用 `ragflow-lite-run` 作为本地启动工作流：它从 `ragflow-lite/openai`、`ragflow-lite/ark` 和 `ragflow-lite/ark-embedding-model` 读取配置，再以对应环境变量启动 `uvicorn ragflow_lite.app:app --reload`。
- `ragflow-lite-run` 被视为用户本地工作流，而不是仓库已提供的脚本或公共接口。

## Key Rotation
- OpenAI key 变更时，覆盖 `pass` 中的 `ragflow-lite/openai`，然后重新执行本地启动工作流。

```bash
read -rsp "NEW OPENAI_API_KEY: " OPENAI_API_KEY; echo
printf '%s\n' "$OPENAI_API_KEY" | pass insert -m -f ragflow-lite/openai
unset OPENAI_API_KEY
```

## Docker Local Snapshot
- 本地 compose 主入口是 `docker compose -f docker/compose.local.yml --profile observability up --build`。
- `app` 容器和本地启动工作流一样，依赖宿主 shell 已导出的 `OPENAI_API_KEY`、`ARK_API_KEY`、`ARK_EMBEDDING_MODEL`；compose 不读取仓库内 `.env`。
- `infinity` 是基础服务；`app`、`prometheus`、`loki`、`alloy`、`grafana` 由 `observability` profile 带起。
- 对宿主的主要端口暴露为：`Infinity` `127.0.0.1:23817` / `127.0.0.1:23820`、`app` `8000`、Prometheus `9090`、Loki `3100`、Grafana `3000`。
- `app` 容器默认源码挂载到 `/workspace`，设置 `PYTHONPATH=/workspace/src`，并运行 `uvicorn ragflow_lite.app:app --reload`。
- `docker/app/Dockerfile.dev` 是 dev-only 镜像定义，包含本地构建依赖和 editable install，不应被当成生产镜像继续扩展。
- observability 栈的更细配置快照包括：Grafana 文件 provisioning、Prometheus scrape `app:8000`、Alloy 读取 Docker socket 并收集容器日志、Loki 本地存储配置。

## Commit Boundary
- 不要把 `.env`、真实密钥、compose 运行产物、日志或截图提交进仓库。
